# JarSol Competition Readiness

## Judge-ready story
**Problem → Proof → Demo → Differentiation → Evidence**

### 1. Problem
Show the concrete user problem JarSol solves before introducing architecture.

### 2. Live demo
Use only flows that can be demonstrated reliably. Label testnet/devnet clearly.

### 3. Differentiation
Focus on the combination of AI/Web4 UX and verifiable Solana infrastructure, not unsupported claims.

### 4. Evidence
Provide:
- repository link
- green CI
- reproducible build commands
- testnet/devnet verification
- architecture diagram
- short demo video

### 5. Pitch rule
Never claim Mainnet deployment, regulatory approval, audited security, real DEX liquidity, or live integrations without current evidence.

## Submission checklist
- [ ] 2–3 minute demo video
- [ ] concise problem statement
- [ ] architecture diagram
- [ ] reproducible repository
- [ ] green CI evidence
- [ ] clear network labels
- [ ] known limitations disclosed
- [ ] future roadmap separated from current functionality
